# Complete venue enrichment: preparation and coverage

Local preparation only. Nothing here is live-release acceptance. Separation must be verified before deployment or activation.

## Independent contracts

Initial unclaimed Free publication requires only: correctly identified real venue and canonical location/page; useful source-supported description; verified venue/associated-operator email; no unresolved critical conflict. A delivery relay, image, event type, capacity, room or facility is not an additional minimum. Qualification grants no delivery authority.

Enrichment seeks all existing supported content within current signed page/request/byte/time/provider budgets. Actual contact forms are observations, never proof that no email exists. A shared address/site/operator does not merge venues.

## Observable gaps

AIRE stores bounded per-field contentCoverage in directory crawl receipts/execution evidence and optional source-discovery replay intelligence. States: OBSERVED, REVIEW_REQUIRED, NOT_OBSERVED in retrieved evidence, BUDGET_LIMITED, RETRIEVAL_BLOCKED, NOT_RETRIEVED or NOT_REQUESTED. Counts and available source URLs/refs are retained. These are extraction observations, not acceptance, approval, absence claims or readiness.

Nexus/Product receipts separately retain accepted/held/operator-precedence/retained-not-projected/capacity/event reasons. Audit the stages plus the actual public page, not just extractor counts.

## Regression scope

All 17 existing practical extractor families have source fixtures. Regressions cover contact/hire/gallery ahead of old news; target body beside thin meta; complete bounded paragraphs preserving late qualifications; UI/sibling rejection; generic section headings/article-name variants; actual forms with footer email; image page lineage; known TortoisePath refused before DNS/HTTP; don't/isn't negatives held; technical PDF individual facility gaps; durable exact-URL404/410; and fatal history-storage failure stopping crawl/current run while preserving usage evidence.

## Controlled operating loop

1. Verify EventSuite separation with release-owner evidence.
2. Finish independent review and frozen-source local gates. Reconcile Product with final controls, preserving eligible Next-only boundary.
3. Verify live schemas/roles/plans read-only; use normal reviewed migration/artifact release. Nexus must adopt the exact reviewed Product runtime, not the old vendor pin.
4. After authorization, apply only reviewed bounded historical404/410 plans. Missing HTTP records/sanitized URLs remain explicit limits. No uncertain legacy failure is cleared for retry.
5. Activate one owned bounded run. Process full frozen inventory before network retries; keep new dynamic first-pass ahead too. Stored-evidence projection is separate from recrawl.
6. Audit a GB/ZA canary against official sources and actual public output across every content family; measure requests/cost/holds/omissions.
7. Each defect becomes a failing retained-source fixture, owner-boundary fix, affected/full retest, independent review, controlled release and fresh audit. Repeat inside current quotas/attempt/backoff limits, never unlimited retries or new paid calls.
8. Stop on history-storage failures, unknown execution accounting, critical identity/source conflicts or budget violations; repair retained evidence and verify before another cycle.

Residual boundaries: optional disputes embedded in independently authored prose are not automatically rewritten; venue-wide capacity and kitchen/sound/lighting lack dedicated public slots; calendar event provenance stays held. These are not solved, and do not become new publication prerequisites.
