# Shared directory bounded runs

The existing standing endpoints now accept signed Last Train Home requests under an explicitly approved `quotaMode: PER_RUN` policy. Older daily policies keep their prior behavior, including existing canary continuations. A version number alone does not select the new mode. The concurrent merged #86 implementation is the authoritative run ledger; the earlier unapplied draft `20261023204000_shared_directory_run_budgets.sql` was withdrawn rather than introducing a second ledger.

The mode requires `maxVenuesPerRun` (at most 500), `maxRequestsPerRun` (at most 2500), and a UUID `directoryContext.runId` inside the HMAC-signed envelope. Nexus first opens the run through the existing signed `/api/integrations/nexus/directory-run` control and finishes it with the same worker/policy binding. Multiple concurrent HTTP requests share that opened durable run. Reservations remain consumed after uncertain execution; lease expiry creates a backed-off retry. Terminal queue replay cannot open another external execution. The ledger retains existing host cooldown, identity lease, retry and zero-paid-provider controls.
